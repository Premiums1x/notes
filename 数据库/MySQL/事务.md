## 并发事务问题：
个人感觉就是“读取数据的数据源问题”，从允许直接读本地的表，到只允许读数据库解决脏读，再通过对数据库进行进一步设置来解决不可重复读、幻读。

1.脏读：
![[Pasted image 20260414111146.png]]

![[Pasted image 20260414111202.png]]
A事务还未执行完（正确执行完才commit），在本地对表进行更新后数据就被事务B读取到了

2.不可重复读：
![[Pasted image 20260414111438.png]]

![[Pasted image 20260414111451.png]]
事务A第1、3步都执行相同查询语句，但第二步时事务B更新了id=1的记录的值并commit更新到数据库在，导致事务A执行相同语句但读到的记录数据不同。

幻读：
![[Pasted image 20260414112023.png]]

![[Pasted image 20260414112035.png]]
事务A第一次读id=1的数据，不存在，然后事务B此时插入id=1的数据，此时事务A再去插入id=1的数据就会因为主键重复、冲突而无法插入，（不可重复读问题已解决，事务A两次读id=1的结果都是相同的），此时事务A再去读id=1的数据依然是不存在的。

### 再往高设置一层事务隔离级别解决不可重复读：
repeatable read:

在一个事务中，执行相同的查询，不会因为另一个事务对数据库的更新而导致读取到不同的值，
执行相同查询始终读到的是相同的结果。

直到正在进行的事务完成后，再去读取才会读取到更新的数据

### 提高事务隔离级别到serializable串行化即可避免幻读
类似于加锁，并发时只一次允许一个事务进行操作，只有等一个事务完成后（提交），其他事务才能接着操作。

所以相同情况，
启动两个事务，A事务查询到一个不存在的数据，
此时，事务B想去插入这条数据时，插入操作就会被阻塞：
![[Pasted image 20260414120813.png]]

因为此时A事务正在执行，B事务只有等A事务执行完毕commit后才能继续，
在A事务中插入了这条数据并commit后，事务B原本要插入但被阻塞的操作再去执行插入时，会报错id=4的记录已存在：
