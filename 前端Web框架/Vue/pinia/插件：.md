本质：**每次创建一个 store 时，自动执行一段逻辑**。
形式：是一个函数，可以选择性地返回要添加到 store 的属性！
可选参数context：上下文
```
export function myPiniaPlugin(context) {
  context.pinia // 用 `createPinia()` 创建的 pinia。
  context.app // 用 `createApp()` 创建的当前应用(仅 Vue 3)。
  context.store // 该插件想扩展的 store
  context.options // 定义传给 `defineStore()` 的 store 的可选对象。
  // ...
}
```

#### 使用插件：`pinia.use()` 将这个函数传给 `pinia`实例。
**必须先 `app.use(pinia)，`插件在挂载时生效，再 `useCounterStore()，插件已就绪，能做拦截`**。否则不生效。

## 给store加新东西：
1. 返回一个含属性对象：
```js
pinia.use(() => ({ hello: 'world' }))
```
所有 store 自动多一个 `hello` 属性，且返回的对象被DevTools 自动追踪。

2. 插件（函数）中直接在参数处获取store，**直接在 store 上挂**
效果一样，但 DevTools 不认识它，要在开发环境手动注册一下：
```js
store._customProperties.add('hello')
```

3. 插件里挂 ref，分两种：
```js
// 定义在插件外——只创建一次
const sharedRef = ref('shared')

pinia.use(({ store }) => {
  // 插件每执行一次，就创建一个新的 ref——每个 store 拿到的是不同的 ref
  store.hello = ref('secret')
  
  // 所有 store 拿到的都是上面那同一个 sharedRef
  store.shared = sharedRef
})
//pinia中操作store是对每一个store都操作，插件则是对每个store都分别执行。
```


## 如何添加新的state：
**要点：插件里加 state 属性时，必须在两个地方同时加。**

|挂在哪儿|目的|
|---|---|
|`store.xxx`|代码里能访问到|
|`store.$state.xxx`|DevTools 能看到 + SSR 能序列化|

步骤：
1. 用 `ref()` 创建响应式数据
2. 挂到 `store.$state` 上
3. 用 `toRef(store.$state, 'key')` 从 $state 提取到 store 上，确保两个路径指向**同一个 ref**
4. 别用 `return` 暴露，不然 DevTools 会显示两份

```js
const hasError = ref(false)
store.$state.hasError = hasError           // ① 挂到 $state
store.hasError = toRef(store.$state, 'hasError')  // ② 挂到 store，两个路径共享同一个 ref
```

> 插件里的 state 变更发生在 store 激活之前，不会触发订阅。

#### Vue 2 兼容：
Vue 2 有响应式限制，动态添加属性必须用 `Vue.set()` / `set()`。

Vue 3 直接赋值就行，Vue 2 得写成：
```js
set(store.$state, 'secret', secretRef)
set(store, 'secret', secretRef)
```

## $reset()相关：
`store.$reset()` 做的事是**把 state 恢复到初始值定义的那个样子**，而在插件里加的state，`$reset` **不认识**，所以要**扣一个自己的 `$reset` 盖上去**：

- 做法：保存原 `$reset` → 执行完自己的清理 → 返回新的 `$reset`。
```js
const originalReset = store.$reset.bind(store)
return {
  $reset() {
    originalReset()       // 先干原活
    store.hasError = false // 再清插件加的
  }
}
```
相当于重写了$reset方法！


## 添加新的外部属性
**放非响应式的东西（第三方类实例、简单值）时，用 `markRaw()` 包一下，告诉 Vue "这玩意儿别代理"。**
`store.router = markRaw(router)  // 路由实例别变响应式，浪费性能
`

**要点：插件里也能订阅 state 变化和 action 调用，统一做日志/持久化。** 没额外语法，就是正常调。


## 自定义选项：
以防抖插件为例：
**思路：定义时声明，插件统一处理。**

**① 定义 store 时写自定义选项**

```js
defineStore('search', {
  actions: {
    searchContacts() { /* 普通函数 */ }
  },
  debounce: { searchContacts: 300 }  // 自定义：这个 action 要防抖 300ms
})
```

**② 插件里读取并替换**

```js
pinia.use(({ options, store }) => {
  if (options.debounce) {
    // 把 action 包一层 debounce，返回替换
    return {
      searchContacts: debounce(store.searchContacts, 300)
    }
  }
})
```

`reduce` 那段只是**同时处理多个 action 的简写**，本质就是上面的写法。

**③ 效果**

狂点 `store.searchContacts()`，只有最后一次执行。

---

**setup 函数风格：** 自定义选项放第三个参数。

```js
defineStore('search', () => { ... }, { debounce: { searchContacts: 300 } })
```

## TypeScript 相关

四个要点，一个逻辑：**插件改了啥，就扩展哪个接口，让 TS 认识它。**

|改了什么|扩展哪个接口|
|---|---|
|往 store 上加新属性（非 state）|`PiniaCustomProperties`|
|往 store 上加新 state|`PiniaCustomStateProperties<S>`|
|给 `defineStore` 加新选项|`DefineStoreOptionsBase<S, Store>`|
|插件函数本身|用 `PiniaPluginContext` 标注参数|

泛型字母别改：`S`=State, `G`=Getters, `A`=Actions, `SS`=Setup Store, `Id`=store 的 id。

## Nuxt：基于 Vue 的全栈框架
Nuxt 是**基于 Vue 的全栈框架**，可以理解为 Vue 的"加强版"。

|      | Vue              | Nuxt                    |
| ---- | ---------------- | ----------------------- |
| 渲染方式 | 纯客户端渲染（SPA）      | 支持 SSR / SSG / CSR，自动处理 |
| 路由   | 手动配 `vue-router` | 按文件目录自动生成               |
| 项目结构 | 自己搭              | 约定好，开箱即用                |

## 与 Pinia 的关系

- **Vue**：`app.use(pinia)`
- **Nuxt**：因有自己的模块/插件系统，需写成 Nuxt 插件
- **本质**：换种方式注册 pinia，逻辑一样

## 注意

刚开始学 Vue + Pinia，Nuxt 部分可以暂时跳过，不影响核心学习。
