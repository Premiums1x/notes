# 浏览器与网络面试复习

> 目标：能把浏览器渲染、URL 访问流程、DNS、TCP、HTTP/HTTPS 这些高频问题稳定地口述出来。

---

## 1. 浏览器渲染流程

推荐主线：

```text
HTML -> DOM
CSS -> CSSOM
DOM + CSSOM -> Render Tree
-> Layout
-> Paint
-> Composite
```

### 面试版回答

浏览器拿到 HTML 后，会先解析 HTML 构建 DOM Tree，同时解析 CSS 构建 CSSOM Tree。然后 DOM 和 CSSOM 结合生成 Render Tree，接着进行 Layout 计算元素的位置和尺寸，再进行 Paint 绘制，最后将各图层 Composite 合成到屏幕上。

---

## 2. DOM 是什么

HTML 本身是一段文本，例如：

```html
<div>
  <p>Hello</p>
</div>
```

浏览器解析后会形成树结构：

```text
div
└── p
    └── Hello
```

JavaScript 操作页面时，实际操作的是浏览器构建出的 DOM 对象。

例如：

```js
const el = document.querySelector("p")
```

拿到的是 DOM 节点对象。

---

## 3. CSSOM 是什么

CSSOM 全称是 CSS Object Model。

它可以理解成浏览器解析 CSS 后形成的样式结构。

### 易错点

不要说成：

```text
CSSDOM
```

正确说法是：

```text
CSSOM
```

---

## 4. Render Tree 是什么

Render Tree 可以简单理解成：

> 浏览器真正准备拿去“画页面”的树。

它由 DOM 和 CSSOM 结合生成。

并不是所有 DOM 节点都会进入 Render Tree，例如：

```css
display: none;
```

这种元素不需要显示，因此通常不会进入渲染树。

---

## 5. Layout 是什么

Layout 负责计算元素的几何信息，例如：

- 宽度
- 高度
- 左右位置
- 上下位置

可以记成：

```text
Layout = 计算位置 + 尺寸
```

---

## 6. Paint 与 Composite

### Paint

把页面视觉内容真正绘制出来，例如：

- 文字
- 背景
- 边框
- 阴影
- 图片

### Composite

现代浏览器可能会把页面拆成多个图层，各图层分别绘制后，再进行合成，最终显示到屏幕上。

面试初级岗位时可以说：

> 布局完成后进行绘制，浏览器可能会对页面进行分层，最后把各图层合成到屏幕上。

---

## 7. 从输入 URL 到页面显示

推荐主流程：

```text
输入 URL
↓
解析 URL
↓
查缓存
↓
DNS 解析
↓
获得服务器 IP
↓
建立 TCP 连接
↓
如果是 HTTPS，进行 TLS 握手
↓
发送 HTTP 请求
↓
服务器处理并返回响应
↓
浏览器解析 HTML / CSS / JS
↓
DOM / CSSOM / Render Tree
↓
Layout / Paint / Composite
↓
页面显示
```

### 面试版回答

浏览器输入 URL 后，首先会解析 URL，然后查询相关缓存并进行 DNS 解析得到服务器 IP。接着建立 TCP 连接，如果是 HTTPS 还要进行 TLS 握手，之后发送 HTTP 请求。服务器返回响应后，浏览器解析 HTML、CSS 和 JavaScript，构建 DOM、CSSOM 和 Render Tree，最后经过 Layout、Paint 和 Composite 将页面显示出来。

---

## 8. 解析 URL 是什么意思

例如：

```text
https://www.example.com/user?id=1
```

浏览器可以拆出：

```text
协议：https
主机名：www.example.com
路径：/user
查询参数：id=1
```

其中：

```text
www.example.com
```

就是主机名，通常也是我们常说的域名。

---

## 9. DNS 是什么

DNS 的核心作用：

```text
域名 -> IP 地址
```

可以把它理解成互联网的“电话簿”。

人更容易记：

```text
www.example.com
```

计算机真正连接服务器时需要的是 IP 地址，所以需要 DNS 进行解析。

---

## 10. 什么叫查 DNS 缓存

浏览器不会每次访问网站都重新向外部 DNS 服务器查询。

它会先看看本地是否已经保存过：

```text
example.com -> 某个 IP
```

如果缓存存在并且没有过期，就可以直接使用。

初级面试可以简单理解为：

```text
浏览器 DNS 缓存
↓
操作系统 DNS 缓存
↓
DNS 服务器
```

---

## 11. DNS 与 UDP

DNS 查询通常比较短，因此常使用 UDP 进行传输。

可以把整个访问过程拆成：

```text
DNS：先问“这个域名对应哪个 IP？”
HTTP：知道 IP 后，再真正访问服务器
```

因此虽然它们属于同一个网页访问流程，但底层使用的协议不一定一样。

初级面试先记：

```text
DNS 查询：通常使用 UDP
HTTP/1.1、HTTP/2：通常基于 TCP
```

---

## 12. TCP 在哪里出现

DNS 得到服务器 IP 后，浏览器需要和服务器建立真正的连接。

传统 HTTP/1.1 和 HTTP/2 通常基于 TCP。

所以可以记：

```text
DNS 找 IP
↓
TCP 建连接
↓
HTTP 发请求
```

如果是 HTTPS：

```text
DNS
↓
TCP
↓
TLS
↓
HTTP
```

---

## 13. HTTP 与 HTTPS

### HTTP

HTTP 默认是明文传输。

### HTTPS

HTTPS 可以简单理解成：

```text
HTTP + TLS
```

在真正传输 HTTP 数据前，会先通过 TLS 建立安全的加密通道。

流程简化为：

```text
TCP 连接
↓
TLS 握手
↓
建立加密通道
↓
HTTP 数据在加密通道中传输
```

### 面试版回答

HTTP 默认是明文传输，而 HTTPS 在 HTTP 之上加入了 TLS，通过 TLS 握手建立加密通道，从而保证传输过程中的安全性。

---

## 当前掌握情况

### 已经能说出主干

- HTML 会解析成 DOM
- CSS 会参与渲染
- DNS 用于域名解析 IP
- HTTP 是明文，HTTPS 使用 TLS
- 网页访问中会涉及 TCP / UDP

### 当前容易混淆

- 浏览器渲染步骤容易只说到 Render Tree，没有继续说 Layout / Paint / Composite
- 容易把 CSSOM 说成 CSSDOM
- “输入 URL 后直接发 GET”不够严谨，前面还有 DNS、TCP、TLS 等步骤
- DNS 和网页 HTTP 请求虽然属于同一大流程，但职责和传输协议不同
