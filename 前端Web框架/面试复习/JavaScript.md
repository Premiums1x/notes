## 1. var、let、const

建议从四个维度回答：

```text
1. 作用域
2. 变量提升
3. 是否允许重复声明
4. 是否允许重新赋值
```

| 特性 | var | let | const |
|---|---|---|---|
| 作用域 | 函数作用域 | 块级作用域 | 块级作用域 |
| 变量提升 | 有 | 有，但存在暂时性死区 | 有，但存在暂时性死区 |
| 声明前访问 | `undefined` | 报错 | 报错 |
| 重复声明 | 可以 | 不可以 | 不可以 |
| 重新赋值 | 可以 | 可以 | 不可以 |

### 面试版回答

`var` 是函数作用域，可以重复声明，也可以重新赋值；`let` 和 `const` 是块级作用域，不能重复声明，其中 `let` 可以重新赋值，`const` 不可以。三者都会在执行前建立变量绑定，但 `var` 在声明前访问时得到 `undefined`，而 `let` 和 `const` 在声明前处于暂时性死区，访问会报错。

## 2. 变量提升

例如：

```js
console.log(a)
var a = 10
```

输出：

```text
undefined
```

可以近似理解为：

```js
var a
console.log(a)
a = 10
```

所以可以先记：

> `var` 的声明像是被提前了，但赋值还留在原来的位置。

### let / const

```js
console.log(a)
let a = 10
```

会直接报错。

原因不是 JavaScript 不知道 `a`，而是执行到 `let a = 10` 之前，`a` 处于暂时性死区（Temporal Dead Zone）。

### 易错点

不要简单背成：

```text
var 有提升，let / const 没有提升
```

更准确的是：

- `var`：声明前访问得到 `undefined`
- `let / const`：声明前处于暂时性死区，访问报错

## 3. 块级作用域与函数作用域

### 块级作用域

通常由 `{}` 形成。

```js
if (true) {
  let a = 10
}

console.log(a) // 报错
```

`let / const` 只在当前代码块中有效。

### 函数作用域

`var` 以整个函数作为作用域边界。

```js
function test() {
  if (true) {
    var a = 10
  }

  console.log(a) // 10
}
```

### 最好这样理解

一个函数内部可能嵌套很多层 `{}`：

- `var` 看整个函数边界；
- `let / const` 看当前 `{}` 代码块边界。

## 5. `==` 和 `===`

### `==`

比较时可能发生隐式类型转换。

```js
1 == "1" // true
```

### `===`

不会进行类型转换，要求类型和值都相同。

```js
1 === "1" // false
```

### 面试版回答

`==` 在比较时可能发生隐式类型转换，而 `===` 不会进行类型转换，只有类型和值都相同才会返回 `true`。实际开发中通常更推荐使用 `===`。

## 6. 闭包

现阶段先不要背太底层的定义，可以先理解为：

> 一个内部函数使用了外部函数中的变量，并且这个内部函数在外部函数执行结束后，仍然能够继续访问这些变量，就形成了闭包。

### 例子

```js
function makeCounter() {
  let count = 0

  return function () {
    count++
    return count
  }
}

const counter = makeCounter()

console.log(counter()) // 1
console.log(counter()) // 2
console.log(counter()) // 3
```

`makeCounter()` 已经执行结束，但返回的内部函数仍然可以访问 `count`，并且能保留之前的状态。

### 更准确一点的说法

内部函数保留了对其创建时词法作用域中变量的引用。

### 常见用途

1. 保存状态
2. 封装私有变量
3. 在回调 / 异步场景中保留上下文

### 面试版回答

闭包是指函数能够访问并保留它创建时外部作用域中的变量，即使外部函数已经执行结束，这些变量仍然可以被内部函数访问。常见用途包括保存状态、封装私有变量等。
