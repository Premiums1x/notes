**匿名内部类并不是 `new` 了一个接口对象。**  
因为接口本身还是**不能实例化**。

它实际做的事是：

**临时定义了一个“没有名字的实现类”，并立刻创建了这个实现类的对象。**

所以你可以理解成：

- `new 接口名() { ... }`
- 表面上看像在 `new` 接口
- 实际上是在 **new 一个匿名实现类对象**
- 这个实现类的实现内容，就写在后面的 `{ ... }` 代码块里

---

看例子：

interface Animal {  
    void speak();  
}

匿名内部类写法：

Animal a = new Animal() {  
    @Override  
    public void speak() {  
        System.out.println("wang");  
    }  
};

---

这段代码**不能理解成**：

new Animal()

因为 `Animal` 是接口，根本不能直接 `new`。

它实际更像编译器偷偷帮你补成了下面这种形式：

class Xxx implements Animal {  
    @Override  
    public void speak() {  
        System.out.println("wang");  
    }  
}  
  
Animal a = new Xxx();

只不过这个 `Xxx`：

- 没有类名
- 你自己也不能直接再复用它
- 只在这一处临时存在

所以才叫**匿名内部类**。

## 为什么变量还是接口类型？

Animal a = new Animal() {  
    @Override  
    public void speak() {  
        System.out.println("wang");  
    }  
};

左边写 `Animal a`，是因为：

- 这个匿名类实现了 `Animal`
- 所以它可以向上转型赋值给 `Animal`

本质上和这个一样：

class Dog implements Animal {  
    @Override  
    public void speak() {  
        System.out.println("wang");  
    }  
}  
  
Animal a = new Dog();

只是匿名内部类把“定义类 + 创建对象”合成一步了。

---

## 再看一个关键点

匿名内部类的 `{ ... }` 里面，不只是“实现接口方法”，也可以写成员：

Animal a = new Animal() {  
    private int age = 3;  
  
    @Override  
    public void speak() {  
        System.out.println("wang");  
    }  
  
    public void run() {  
        System.out.println("run");  
    }  
};

说明这个代码块本质上真的是在**定义一个类体**。

但是因为左边引用类型是 `Animal`：

a.speak(); // 可以  
a.run();   // 不行

还是那句话：

**对象实际是匿名实现类对象，但引用类型是接口类型，所以只能调用接口中声明的方法。**
