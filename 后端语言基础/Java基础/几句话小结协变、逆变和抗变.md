### 泛型

泛型默认是**不变**的，不是抗变。  
也就是说，对于有泛型参数的对象来说，即使泛型参数之间有父子关系，这两个泛型对象本身也**没有关系**。

比如：

```java
Test<Integer> != Test<Number>
```

它们不能直接互相赋值。

---

但是如果给泛型类设置上界：`? extends ...`

就会表现出一种**协变效果**，也就是可以用“父类型通配符”去接收“子类型泛型对象”。

如：

```java
Test<? extends Number> test = new Test<Integer>(10);
```

这里表示：`test` 里面存的是 **某个 Number 的子类**，但具体是哪一个并不知道。

所以这种情况下，一般**可以读取数据，而不能修改数据**（除了 `null`）。  
因为你虽然知道它一定是 `Number` 的某个子类，但你不知道它到底是 `Integer`、`Double` 还是什么类型，如果随意修改，就可能造成类型不安全。

所以协变一般用来**读取数据**，而不是**修改数据**。

这一点和数组有些类似。数组本身支持协变，比如：

```java
Object[] arr = new Integer[10];
arr[0] = "hello";
```

这里编译能过，但运行时会抛出错误，因为底层实际是 `Integer[]`，却存入了 `String`。  
Java 泛型为了避免这种类型存储错误，在这里就做了更严格的限制。

---

给泛型设置下界就反过来了：`? super Number`

这样表示这个泛型参数是 **Number 或者 Number 的父类**。

如：

```java
Test<? super Number> test = new Test<Object>();
```

这种情况下，就**可以对泛型对象做修改**，因为无论它实际是 `Number` 还是 `Object`，都可以安全接收 `Number` 或者 `Number` 的子类。

但是读取时就只能用**最大的公共类型 `Object`** 去接。

原因是这里限定的只是：它一定是 `Number` 的某个父类，但具体是 `Number` 还是 `Object` 不确定。  
如果实际给的是 `Object`，那你再用 `Number` 去接收读取出来的值，就不安全了。  
所以为了保证类型不出错，读取时只能按 `Object` 来处理。

---

### 总结

- 泛型默认是**不变**
    
- `? extends T`：适合**读**，不适合**写**
    
- `? super T`：适合**写**，读出来一般只能当 `Object`
    

一句话记：

> extends 负责读，super 负责写
