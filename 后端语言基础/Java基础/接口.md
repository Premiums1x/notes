之所以要用接口类的变量去接受引用，是要让这个引用只能看见接口所定义的功能，而非实现类的完整功能。

注意，是**引用被限制了**，不是**对象被限制了**。

---

看这个例子：

`interface Animal {`  
    `void speak();`  
`}`  
  
`class Dog implements Animal {`  
    `@Override`  
    `public void speak() {`  
        `System.out.println("wang");`  
    `}`  
  
    public void watchHome() {  
        System.out.println("看家");  
    }  
`}`

然后：

`Animal a = new Dog();`  
`a.speak();      // 可以`  
`a.watchHome();  // 不可以，编译报错`

这里不是 `Dog` 对象真的不会 `watchHome()`，而是：

- `Dog` 对象其实有 `watchHome()`
- 但你现在用的是 `Animal` 类型变量 `a`
- 编译器只允许你调用 `Animal` 里声明过的方法

所以本质是：

**对象能力没有少，只是你拿着“接口视角”去看它时，只能用接口那部分能力。**
