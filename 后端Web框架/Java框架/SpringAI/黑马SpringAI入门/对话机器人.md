### 会话记忆：
![[Pasted image 20260523192422.png]]

message数组里还有一个角色是assistant：大模型本身的回复，我们实现记忆就是不断把聊天记录封装追加到message数组里，每次对话都携带发给大模型。

**通过环绕增强的advisor**，帮助记录每次会话的历史并拼接到message数组中。

如何实现？
1. 定义会话存储方式
![[Pasted image 20260523193213.png]]
通过实现`ChatMemory`接口实现，其有默认实现类：存放在内存中


2. 配置会话记忆
![[Pasted image 20260523193546.png]]
选择ChatMemory实现类后，用`@Bean`注解注入对象。
并在客户端配置处添加上“消息会话增强”的增强环绕Advisor，传入我们创建好的会话记忆存储方案。
将来其就会去拦截与大模型的对话并记录会话历史，同时在发请求时进行会话记录拼接，**千万注意要使用会话ID来管理**


都换用了构造器方法：`MessageWindowChatMemory.builder().build();`,
`MessageChatMemoryAdvisor.builder(chatMemory()).build()`
而非直接new

3. 添加会话id，方便管理
![[Pasted image 20260523194021.png]]

发请求时添加`.advisors()`方法，向Advisor的上下文中添加一组键值对，key是SpringAI写好的固定常量，value是**前端传入的会话id**，且所有advisor都可见（包括刚刚在会话记忆中配置的advisor），这样它就能拿到会话id去做会话管理。


#### 记忆混乱：
此时我们没有传入ChatID去实现不同会话的管理，大模型会糅合全部会话记录认为是同一用户。

##### 解决：
前端来管理会话id，每次请求都带上ChatID，如果是相同会话就携带的相同id，后端就能识别到。新对话就会创建新id，同理，用以区分不同会话。
