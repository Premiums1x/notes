1. AutoGen： 由多个可对话智能体组成，我们为每个智能体赋予不同身份、职责，如定义不同角色（Coder, ProductManager, Tester），并设定它们之间的交互规则（例如，Coder 写完代码后由 Tester 自动接管）。其“群聊”机制：`RoundRobinGroupChat`实例化后将需要参与协作的智能体加入，能将复杂的协作变为按照预设规则流动的消息传递，最终完成任务。

封装了两种智能体实现类：

- `AssistantAgent`,实例化以创建具有特定功能和技能的智能体。
- `UserProxyAgent`一个特殊的智能体，它不依赖 LLM 进行回复，而是作为用户在系统中的代理，既是用户的化身：向多智能体系统发起任务。也是任务完成验收的化身：负责在任务最终完成后发出 TERMINATE 指令，以正常结束整个协作流程。

2. AgentScope：

特点：组合式架构和消息驱动模式: 将智能体之间的通信行为统一抽象为消息`Msg`,并自带`MsgHub`消息中心，支持消息持久化及消息路由（本地、远程服务器）, `pinepipe`支持智能体间进行异步通信、并发能力强。

内置的消息传递机制和对分布式部署的支持，使其非常适合构建和运维复杂、大规模的多智能体系统。易于构建多智能体应用。

缺点：框架较重，适合需要构建大规模、高可靠性的多智能体系统，若需快速开发原型或只需实现简单多智能体应用，应该用更轻量的框架。

3. CAMEL： 核心理念是：最少化人类干预，让两个智能体通过“角色扮演”自主协作解决复杂任务。

两个理念：角色扮演、引导性提示

这个架构一般设立两个智能体：AI User负责提出需求、给出没一步具体操作，AI Assistant 负责执行每一步具体操作。

角色扮演：二者的身份配置更像是两个人在跨领域合作，但缺少一方就无法完成复杂任务。

引导性提示：含 当前角色、协作者角色、共同目标、行为约束和沟通协议（保证两个智能体的工作方向不偏离任务目标）

4. LangGraph： 不同于消息单向流动的链式结构，它将智能体每步操作定义为图中的一个节点，用边定义节点跳转逻辑，这种设计天然支持循环 (Cycles)，使得实现如 Reflection 这样的迭代、修正、自我反思的复杂工作流变得异常简单和直观。

LangGraph 将智能体的执行流程建模为一种状态机（State Machine），并将其表示为有向图（Directed Graph），每个节点代表一个“计算”（LLM调用、调用工具...），每条边代表节点跳转逻辑，所以LangGraph原生支持循环，对于构建“思考、行动、反思”进行自我迭代的的智能体工作流很便利。

- 全局状态（State），通常用python的`TypedDict`，存储所有需要追踪的信息：历史记录、当前任务....
- 节点：一个函数，作为工作单元，接收当前状态，返回执行后的最新状态。每个节点都可以读取该结构中的数据，并对其进行更新。
- 边：一般有向边：决定节点的输入流向新的节点的方向。*LangGraph 最强大的功能在于条件边（Conditional Edges）。它通过一个函数来判断当前的状态，然后动态地决定下一步应该跳转到哪个节点*,这很好地实现了对循环、分支的“分流”
