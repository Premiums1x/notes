一个涉及将权限管理、系统设置等多方面的页面进行集成的npm包。

接到需求：修改一个组件页面，但是无论如何都找不到这个组件的文件，在view里找、顺着接口找、在资源管理页面找资源路径...等等方法都找不到。

最后排查出来这个组件存在于公司一个封装好的npm包，代码是打包编译后的js代码而非vue文件，npm包在node_modules里都找不到，源码在source-map里，同样看不见找不到，无法修改。

项目安装后，只能使用其暴露出来的API进行配置使用。

没招，老大叫重构个页面在资源管理给它配置替换掉。

这种引用的组件存在于npm包里的形式还是我第一次见，探究了下项目中使用的路径：

```
先在vue应用注册这个插件：
Vue.use(引入插件名，配置对象，包含store项)，
项目启动时加载，并把 插件 的权限模块注册到 Vuex 中。

用户访问页面时，先登录并获取权限菜单：
permission = 插件.initSecurity(...)

然后
插件.getPermissionInfo()
它会请求一个接口，
后端返回的不是组件代码，而是菜单信息，例如：
{
  code: 'xxx_aabbManage',
  href: '/xxx/aabbManage',
  name: '账号管理'
}

插件的 包内部根据 code 找到自己的组件
插件包内部其实有一套路由表：
{
  code: 'xxx_aabbManage',
  path: '/xxx/aabbManage',
  component: aabbManage
}
这里的 aabbManage 就是已经编译进 @npm包的 Vue 组件。
然后它会把组件塞回后端菜单：
{
  code: 'xxx_aabbManage',
  href: '/xxx/aabbManage',
  component: aabbManage
}

当前项目把这个路由动态加入 Vue Router

当前项目会判断：
if (!_.isObject(component)) {
  component = require(`@/views${componentPath}`)
}

关键点是：
普通业务页面：component 是字符串，需要从 src/views 加载
依赖包的 页面：component 已经是组件对象，不需要从 src/views 加载

最后：
router.addRoutes(...)

于是访问：
/xxx/aabbManage
Vue Router 直接渲染  依赖包里的 aabbManage 组件。

整体就是：

后端返回菜单 code
        ↓
依赖 包根据 code 找内部组件
        ↓
生成动态路由
        ↓
Vue Router 添加路由
        ↓
显示 依赖包 页面
```
