后端根据pageSize返回一页的数据量，然后总数也是后端返回的，页数由组件自动计算，而点击页数时就相当于执行一次查询query方法向后端请求当前页数据，将新的currentPage作为入参。

机制：
1. **按需索取，只查当页**： 后端在数据库执行分页查询（类似 `LIMIT pageSize OFFSET (currentPage-1)*pageSize`），所以只返回这一页对应数量的数据给前端 `content`，极大地减轻了网络传输和浏览器的渲染负担。
2. **总数与页码运算**： 后端同时执行 `COUNT(*)` 查出总记录数 `total` 返回给前端；组件内部自动根据公式 `Math.ceil(total / pageSize)` **自动运算**出总页数，并生成分页按钮。
3. **交互即重新查询**： 当用户在界面点击某个页码时，组件内部自动将新的页码赋给 `currentPage`，然后触发 `@query` 执行查询方法，把新的 `currentPage` 带给后端索取下一页数据。

## Vue 接入分页接口的完整写法（博客笔记）

### Vue 接入分页列表接口开发笔记

在 Vue 组件中接入后端分页列表接口的标准开发范式：

#### 1. 核心状态管理 (Data)

要实现完整的分页逻辑，除了存放数据的列表变量外，至少还需要维护三个专门的分页状态变量。

```javascript
data() {
  return {
    // 数据源
    reportList: [],      // 列表数据

    // 分页三大金刚
    pageIndex: 1,        // 当前页码 (初始值为 1)
    pageSize: 10,        // 每页条数 (根据需求定义，如 10, 20, 50)
    total: 0,            // 数据总条数 (由后端返回，用于渲染分页组件的页码)

    // 体验优化(可选)
    loading: false       // 加载状态，用于表格 loading 动画和防抖
  }
}
```

#### 2. 核心请求封装 (Method)

需要封装一个专门的方法用来组装参数并调用 API 接口。

##### 核心步骤：

1. **组装 Payload**：将筛选表单的内容（如 `this.filter`）和当前的分页参数组合在一起。
2. **发送请求**：调用 API 方法（如 `getExamReportList`）。
3. **响应赋值**：将接口返回的列表和总数分别赋值给 `reportList` 和 `total`。

```javascript
methods: {
  async fetchReportList() {
    this.loading = true;

    // 1. 组装参数
    const params = {
      model: { ...this.filter }, // 筛选条件
      pageIndex: this.pageIndex, // 注入当前页码
      pageSize: this.pageSize    // 注入每页条数
    };

    try {
      // 2. 调用接口
      const res = await getExamReportList(params);

      // 3. 响应赋值 (注意根据实际接口数据结构取值)
      if (res.code === 200) {
        this.reportList = res.data.list || [];
        this.total = res.data.total || 0;
      }
    } catch (error) {
      console.error('获取列表失败:', error);
    } finally {
      this.loading = false;
    }
  }
}
```

#### 3. 各种场景下的分页变量维护规则

这是分页最容易出 Bug 的地方。在不同的用户交互场景下，对 `pageIndex` 的处理规则是完全不同的。

> [!IMPORTANT] **黄金法则：** 只要是**触发数据过滤/重新洗牌**的操作，必须重置页码到第 1 页。只有单纯的分页跳转，才保留筛选条件并改变页码。

| 用户操作场景 | `pageIndex` 的处理 | 附加操作 | 逻辑解释 |
| --- | --- | --- | --- |
| **初始加载** (页面进入) | 保持默认 `1` | 执行 `fetchReportList()` | 首次获取第 1 页数据 |
| **点击“查询”按钮** | **强制重置为 `1`** | 执行 `fetchReportList()` | 条件改变了，之前的页码无意义。如果当前在第 5 页换条件查询，新结果可能只有 2 页，不置 1 会查出空数据。 |
| **点击“重置”按钮** | **强制重置为 `1`** | 清空 `filter`，执行 `fetchReportList()` | 恢复到最原始的初始状态。 |
| **切换“每页条数”(pageSize)** | **强制重置为 `1`** | 将 `pageSize` 设为新值，执行 `fetchReportList()` | 每页条数变了，总页数和数据分布全变了，必须回到第 1 页重新看起。 |
| **点击“第N页/下一页”** | **赋值为目标页码 `N`** | 执行 `fetchReportList()` | **切记不要**清空 `filter`！必须带着当前的筛选条件去请求下一页。 |

#### 4. UI 视图层的交互绑定 (Template)

在使用 Element UI 等组件库时，通常在 `<table>` 下方配置分页组件，将变量和事件绑定上去。

```html
<!-- 分页组件示例 (以 Element UI 为例) -->
<el-pagination
  background
  layout="total, sizes, prev, pager, next, jumper"
  :current-page="pageIndex"       <!-- 绑定当前页码 -->
  :page-size="pageSize"           <!-- 绑定每页条数 -->
  :total="total"                  <!-- 绑定总条数 -->
  :page-sizes="[10, 20, 50, 100]" <!-- 可选的每页条数 -->
  @current-change="handleCurrentChange" <!-- 页码改变的回调 -->
  @size-change="handleSizeChange"       <!-- 条数改变的回调 -->
>
</el-pagination>
```

##### 对应的事件回调：

```javascript
methods: {
  // 1. 页码改变 (翻页)
  handleCurrentChange(val) {
    this.pageIndex = val;
    this.fetchReportList(); // 带上现有条件查新的一页
  },

  // 2. 每页条数改变
  handleSizeChange(val) {
    this.pageSize = val;
    this.pageIndex = 1;     // 重要：重置回第一页
    this.fetchReportList();
  },

  // 3. 点击查询按钮
  onSearch() {
    this.pageIndex = 1;     // 重要：重置回第一页
    this.fetchReportList();
  },

  // 4. 点击重置按钮
  onReset() {
    this.filter = { /* 恢复初始状态 */ };
    this.pageIndex = 1;     // 重要：重置回第一页
    this.fetchReportList();
  }
}
```
