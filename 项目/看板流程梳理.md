## 一、应用启动流程

```
用户访问 http://localhost:5173
    ↓
浏览器加载 index.html
    ↓
main.ts 执行
    ↓
┌─────────────────────────────────────────┐
│  enableMock()                            │
│  ├─ 开发环境才执行                        │
│  └─ 启动 MSW Mock Worker                │
│     └─ 拦截 /api/* 请求，使用内存数据    │
└─────────────────────────────────────────┘
    ↓
创建 Vue 应用实例
    ↓
setupAntd(app)        // 注册 Ant Design Vue
    ↓
app.use(pinia)         // 注册 Pinia 状态管理
    ↓
app.use(router)        // 注册 Vue Router
    ↓
注册 v-permission 指令
    ↓
注册 Permission 组件
    ↓
app.mount('#app')      // 挂载到 DOM
    ↓
App.vue 渲染 <RouterView />
    ↓
路由跳转到 /login（因为未登录）
```

**关键文件：**
- `src/main.ts` - 应用入口
- `src/mocks/browser.ts` - MSW Mock 启动
- `public/mockServiceWorker.js` - Mock Worker 脚本

## 三、路由守卫流程

每次路由跳转都会触发 `router.beforeEach` 守卫：

```
用户发起路由跳转（如点击菜单）
    ↓
┌─────────────────────────────────────────┐
│  router.beforeEach 守卫执行             │
└─────────────────────────────────────────┘
    ↓
【检查 1】是 404 路由且未登录？
    ├─ 是 → 跳转 /login（带 redirect）
    └─ 否 → 继续
    ↓
【检查 2】未登录且非公开路由？
    ├─ 是 → 跳转 /login（带 redirect）
    └─ 否 → 继续
    ↓
【检查 3】已登录但目标路径是 /login？
    ├─ 是 → 跳转 /dashboard
    └─ 否 → 继续
    ↓
【检查 4】已登录但还没有用户信息？
    ├─ 是 → 调用 authStore.me()
    │        ├─ 成功 → 继续
    │        └─ 失败 → logout() + 跳 /login
    └─ 否 → 继续
    ↓
【检查 5】已登录但 isRouteReady = false？
    ├─ 是 → 调用 permissionStore.generateRoutes()
    │        ├─ 生成动态路由
    │        └─ isRouteReady = true
    │        → return to.fullPath（重新跳转）
    └─ 否 → 继续
    ↓
【检查 6】目标路由有 permission 权限码？
    ├─ 是 → 检查 permissionStore.hasPermission(code)
    │        ├─ 有权限 → 放行
    │        └─ 无权限 → 跳 /403
    └─ 否 → 放行
    ↓
返回 true（允许访问）
```

**关键文件：**
- `src/router/guard.ts` - 路由守卫逻辑
- `src/router/index.ts` - 路由配置与守卫注册

## 四、动态路由生成流程

```
permissionStore.generateRoutes(router)
    ↓
GET /api/auth/menu
    ↓
┌─────────────────────────────────────────┐
│  Mock 根据用户角色返回菜单数据：          │
│  {                                      │
│    menus: [                             │
│      {                                  │
│        path: "/dashboard",              │
│        name: "Dashboard",              │
│        title: "仪表盘",                │
│        icon: "dashboard",               │
│        component: "DashboardView"       │
│      },                                 │
│      ...                                │
│    ],                                   │
│    permissions: ["ticket:view", ...]    │
│  }                                      │
└─────────────────────────────────────────┘
    ↓
transformMenuToRoutes(data.menus)
    ↓
┌─────────────────────────────────────────┐
│  菜单数据转换成 Vue Router 配置：        │
│  {                                      │
│    path: "/dashboard",                  │
│    name: "Dashboard",                  │
│    component: () => import(...),       │
│    meta: {                             │
│      title: "仪表盘",                  │
│      permission: "dashboard:view",      │
│      keepAlive: true                    │
│    }                                   │
│  }                                      │
└─────────────────────────────────────────┘
    ↓
router.addRoute('Root', route)
    ↓
记录动态路由名称到 dynamicRouteNames[]
    ↓
isRouteReady = true  ✓
    ↓
permissionStore.menus = 菜单数据
permissionStore.codes = 权限码数组
```

**关键文件：**
- `src/store/permission.ts` - 权限状态管理
- `src/router/dynamicRoutes.ts` - 菜单转路由逻辑
- `src/mocks/handlers.ts` - Mock 菜单接口

**组件映射表（dynamicRoutes.ts）：**

## 五、业务请求流程

以工单列表查询为例：

```
用户访问工单列表页 /ticket/list
    ↓
页面组件 mounted
    ↓
api/ticket.getTicketListApi(params)
    ↓
request.get('/api/tickets', params)
    ↓
┌─────────────────────────────────────────┐
│  请求拦截器 (utils/request/index.ts)     │
│                                         │
│  1. 获取 accessToken                     │
│  2. 设置 Authorization: Bearer xxx      │
│  3. 创建 AbortController（用于取消）     │
└─────────────────────────────────────────┘
    ↓
发送请求到 MSW Mock（或真实后端）
    ↓
┌─────────────────────────────────────────┐
│  Mock 处理：                            │
│  1. 从 Authorization 获取 token          │
│  2. 解析 token 获取租户 id               │
│  3. 根据查询参数筛选数据                 │
│  4. 返回分页数据                        │
└─────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────┐
│  响应拦截器：                            │
│  1. 清理 AbortController                │
│  2. 检查 response.data.code             │
│     ├─ code === 0 → 返回 data           │
│     ├─ code === 401 → 触发 Token 刷新   │
│     └─ 其他 → 错误提示                   │
└─────────────────────────────────────────┘
    ↓
返回数据到页面组件
    ↓
更新页面 state（tableData, total, loading）
```

**关键文件：**
- `src/utils/request/index.ts` - Axios 封装
- `src/api/ticket.ts` - 工单 API
- `src/mocks/handlers.ts` - Mock 业务接口

## 六、Token 刷新流程

当请求返回 401 时触发：

```
某业务请求返回 401
    ↓
handleUnauthorized(config)
    ↓
【检查】是否设置了 skipAuthRefresh？
    ├─ 是 → 跳转 /login（不刷新）
    └─ 否 → 继续
    ↓
标记 config._retry = true（防止死循环）
    ↓
【检查】是否正在刷新 token？
    ├─ 是 → 将请求加入 refreshQueue 排队
    │       ↓
    │       等待刷新完成
    │       ↓
    │       用新 token 重放请求
    │
    └─ 否 → 开始刷新
           ↓
           POST /api/auth/refresh
           ↓
           ┌─────────────────────────────┐
           │  Mock 返回新的 token：         │
           │  {                          │
           │    accessToken: "new-xxx",   │
           │    refreshToken: "new-yyy"   │
           │  }                          │
           └─────────────────────────────┘
           ↓
           更新 token（localStorage + Pinia）
           ↓
           flushRefreshQueue(null, newToken)
           ↓
           唤醒队列中的所有请求
           ↓
           isRefreshing = false
```

**并发请求场景：**

```
同时发出 3 个请求（都 401 了）
    ↓
第 1 个请求 → 开始刷新 token
    ↓
第 2 个请求 → 检测到 isRefreshing = true
              → 加入队列等待
    ↓
第 3 个请求 → 检测到 isRefreshing = true
              → 加入队列等待
    ↓
刷新完成
    ↓
用新 token 重放这 3 个请求
```

**关键文件：**
- `src/utils/request/index.ts` - Token 刷新逻辑
- `src/utils/request/token.ts` - Token 存取工具

## 七、退出登录流程

```
用户点击右上角头像 → 退出登录
    ↓
authStore.logout()
    ├─ accessToken = ''
    ├─ refreshToken = ''
    ├─ tenantId = ''
    ├─ user = null
    └─ 清空 localStorage 中的 token
    ↓
permissionStore.resetDynamicRoutes(router)
    ├─ 遍历 dynamicRouteNames[]
    │   └─ router.removeRoute(name)
    ├─ dynamicRouteNames = []
    ├─ codes = []
    ├─ menus = []
    └─ isRouteReady = false
    ↓
appStore.resetTabs()
    ├─ tabs = [Dashboard]
    └─ activeTabPath = '/dashboard'
    ↓
router.replace('/login')
```

**关键文件：**
- `src/store/auth.ts` - logout 方法
- `src/store/permission.ts` - resetDynamicRoutes 方法
- `src/layout/index.vue` - 退出按钮处理

## 九、权限控制详解

### 9.1 三层权限控制

| 层级 | 控制方式 | 位置 |
|-----|---------|------|
| 路由级 | router.beforeEach 检查 permission | `src/router/guard.ts` |
| 菜单级 | 后端返回已筛选的菜单数据 | Mock 中根据角色过滤 |
| 按钮级 | v-permission 指令或 Permission 组件 | 页面内使用 |

### 9.2 路由级权限

```typescript
// src/router/guard.ts
const permissionCode = to.meta.permission as string
if (permissionCode && !permissionStore.hasPermission(permissionCode)) {
  return '/403'  // 无权限跳转 403
}
```

### 9.3 按钮级权限

**指令方式：**
```vue
<a-button v-permission="'ticket:create'">新建</a-button>
```

**组件方式：**
```vue
<Permission code="ticket:edit">
  <a-button>编辑</a-button>
</Permission>
```

### 9.4 权限码对照表

| 模块 | 权限码 | 说明 |
|-----|-------|------|
| 工单 | ticket:view | 查看工单 |
| 工单 | ticket:create | 新建工单 |
| 工单 | ticket:edit | 编辑工单 |
| 资产 | asset:view | 查看资产 |
| 资产 | asset:create | 新建资产 |
| 资产 | asset:edit | 编辑资产 |
| 知识库 | kb:view | 查看知识库 |
| 知识库 | kb:edit | 编辑知识库 |

### 9.5 Mock 中根据角色返回权限

```typescript
// src/mocks/db.ts (简化示例)
const ROLE_PERMISSIONS: Record<string, string[]> = {
  admin: ['ticket:view', 'ticket:create', 'ticket:edit', ...],
  staff: ['ticket:view', 'ticket:create', ...],
  guest: ['ticket:view', ...],
}
```

## 十、标签页管理流程

```
用户访问某个页面（如 /ticket/list）
    ↓
┌─────────────────────────────────────────┐
│  layout/index.vue 监听 route.fullPath  │
└─────────────────────────────────────────┘
    ↓
appStore.addTabByRoute(route)
    ↓
【检查】tab 是否已存在？
    ├─ 存在 → 不添加
    └─ 不存在 → 添加到 tabs[]
           ↓
           tabs.push({
             title: route.meta.title,
             path: route.path,
             name: route.name,
             closable: path !== '/dashboard',
             keepAlive: route.meta.keepAlive
           })
    ↓
设置 activeTabPath = 当前路径
    ↓
标签页高亮显示
```

### 关闭标签页流程：

```
用户点击标签页的关闭按钮
    ↓
appStore.removeTabByPath(path)
    ↓
从 tabs[] 中移除该标签
    ↓
【检查】关闭的是否是当前标签？
    ├─ 是 → 跳转到最后一个标签
    └─ 否 → 不做操作
    ↓
Keep-alive 根据 cachedTabNames 清理缓存
```

**关键文件：**
- `src/layout/index.vue` - 标签页 UI
- `src/store/app.ts` - 标签页状态管理

## 附录：关键状态一览

### authStore 状态
```typescript
{
  accessToken: string      // 访问令牌
  refreshToken: string     // 刷新令牌
  tenantId: string         // 当前租户 ID
  user: UserProfile | null // 用户信息
}
```

### permissionStore 状态
```typescript
{
  codes: string[]          // 权限码数组
  menus: MenuItemDto[]     // 菜单数据
  isRouteReady: boolean    // 动态路由是否已生成
  dynamicRouteNames: string[] // 动态路由名称列表
}
```

### appStore 状态
```typescript
{
  collapsed: boolean       // 侧边栏是否折叠
  tabs: TabItem[]         // 标签页列表
  activeTabPath: string   // 当前激活的标签路径
}
```
