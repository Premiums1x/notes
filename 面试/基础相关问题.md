### Vuex 的五个核心概念

理解 Vuex 就是理解这五个核心属性：

1. **State（数据源）：**
    
    - 相当于组件中的 `data`。
        
    - 这是单一状态树，存储应用中所有的共享数据。
        
2. **Getters（计算属性）：**
    
    - 相当于组件中的 `computed`。
        
    - 用于对 State 进行过滤、计算或处理（例如：从 Todo 列表中过滤出“已完成”的项目）。
        
3. **Mutations（同步更改）：**
    
    - **关键点：** 这是更改 Vuex 中 State 的**唯一**方法。
        
    - 必须是**同步**函数。
        
    - 使用 `store.commit('mutationName')` 来触发。
        
4. **Actions（异步操作）：**
    
    - 相当于组件中的 `methods`，但专门用于处理异步逻辑（如 API 请求）。
        
    - Action **不能直接修改 State**，它必须提交（commit）Mutation 来修改。
        
    - 使用 `store.dispatch('actionName')` 来触发。
        
5. **Modules（模块化）：**
    
    - 当应用很大时，Store 对象会变得臃肿。Module 允许我们将 Store 分割成模块（user 模块、cart 模块等），每个模块拥有自己的 state、mutation 等。

2. CSS 怎么画一个大小为父元素面积一半的正方形

这是一个数学题转 CSS 题。假设父元素也是正方形。

- **数学原理：** 面积是边长的平方。如果面积减半 ($Area = 0.5$), 边长则变为原来的 $\sqrt{0.5} \approx 0.707$。
    
- **实现：** 设置子元素的宽和高为 `70.7%`。
    
    CSS
    
    ```
    .child {
      width: 70.7%;
      height: 70.7%;
    }
    ```
    
- **替代方案（利用 Transform）：** 宽高设为 100%，然后 `transform: scale(0.707)`。

**5. Promise 有几个状态，怎么理解 ES6 Promise，使用场景？**

- **三个状态：** `Pending` (进行中)、`Fulfilled/Resolved` (已成功)、`Rejected` (已失败)。状态一旦改变不可逆。
    
- **理解：** Promise 是异步编程的一种解决方案，解决了回调地狱 (Callback Hell) 的问题，使代码更易读（链式调用）。
    
- **使用场景：** 网络请求 (Axios/Fetch)、文件读取、定时器封装等异步操作。
    

**6. Promise.catch 后面的 .then 还会执行吗？**

- **会执行。** `Promise.catch` 本身也会返回一个新的 Promise。如果 `catch` 回调里没有抛出新的错误，它返回的 Promise 状态是 fulfilled，因此后续的 `.then` 会继续执行。
    

**7. 浏览器同源策略 (Same-Origin Policy)**

- 浏览器的一种安全机制，限制一个源 (Origin) 的文档或脚本与另一个源的资源进行交互。
    
- **同源定义：** 协议 (Protocol)、域名 (Domain)、端口 (Port) 三者必须完全相同。
    

**8. 如何解决跨域问题**

- **CORS (跨域资源共享)：** 目前最主流的方案，后端设置响应头 `Access-Control-Allow-Origin` 等。
    
- **Nginx 反向代理 / 开发环境 Proxy：** 前端请求发给同源的代理服务器，由服务器转发给目标服务器（服务器之间没有跨域限制）。
    
- **JSONP：** 利用 `<script>` 标签不受同源策略限制的特性（仅支持 GET）。
    
- **WebSocket：** 协议本身支持跨域。
    

**9. 给一个 DOM 同时绑定两个点击事件（一个捕获，一个冒泡），执行次数和顺序？**

- **执行次数：** 2次。
    
- **执行顺序：**
    
    - 通常 DOM 事件流是：**捕获阶段 (Capture) -> 目标阶段 (Target) -> 冒泡阶段 (Bubble)**。
        
    - **先执行捕获，后执行冒泡**。
        
    - _细节补充：_ 如果点击的就是这个 DOM 元素本身（处于目标阶段），在现代浏览器中，通常按照**代码绑定的先后顺序**执行。但如果面试官问的是标准流，回答“先捕获后冒泡”是标准答案。
        

**10 & 11. 深浅拷贝 (区别、实现方法)**

- **区别：**
    
    - **浅拷贝 (Shallow Copy)：** 拷贝对象的第一层属性。如果是基本类型拷贝值，如果是引用类型拷贝内存地址。修改新对象会影响原对象。
        
    - **深拷贝 (Deep Copy)：** 递归拷贝所有层级，开辟新的内存空间。修改新对象**不**影响原对象。
        
- **深拷贝实现方法：**
    
    1. `JSON.parse(JSON.stringify(obj))` (最简单，但不支持函数、undefined、Symbol、循环引用)。
        
    2. **递归实现** (手写 deepClone 函数)。
        
    3. `lodash.cloneDeep` (第三方库)。
        
    4. `structuredClone(obj)` (现代浏览器原生支持)。

### 17. Vue 响应式原理 (重点)

面试时建议分别通过 Vue 2 和 Vue 3 来回答，体现你对技术迭代的理解。

- **核心概念：** 数据劫持 + 观察者模式。
    
- **Vue 2 (Object.defineProperty)：**
    
    - **实现：** 递归遍历 data 对象的所有属性，使用 `Object.defineProperty` 将属性转化为 `getter/setter`。
        
    - **流程：** 读取数据触发 `get` 进行依赖收集（收集 Watcher），修改数据触发 `set` 通知 Watcher 更新视图。
        
    - **缺陷：**
        
        - 无法检测对象属性的**新增**或**删除** (需要用 `$set`)。
            
        - 无法直接监控**数组**下标的变化 (Vue 2 重写了数组方法来解决)。
            
        - 初始化时递归遍历深层对象，性能开销大。
            
- **Vue 3 (Proxy) —— _你正在学的_**：
    
    - **实现：** 使用 ES6 的 `Proxy` 对象代理整个 data 对象。
        
    - **优势：**
        
        - 可以直接拦截对象属性的读取、修改、删除、新增等操作。
            
        - 支持监听数组的变化。
            
        - 支持 Map、Set 等数据结构。
            
        - **懒代理：** 只有访问到深层属性时才会去代理它，性能更好。

### 18. Webpack 的 Loader 和 Plugin 区别

这是一个考察工程化理解的高频题。

- **Loader (加载器)：**
    
    - **作用：** “翻译官”。Webpack 本身只认识 JavaScript 和 JSON，Loader 让 Webpack 能够去处理其他类型的文件。
        
    - **功能：** 将非 JS 文件转换成 Webpack 能识别的模块。
        
    - **例子：**
        
        - `css-loader` / `style-loader`：处理 CSS。
            
        - `vue-loader`：将 `.vue` 文件转为 JS。
            
        - `babel-loader`：将 ES6+ 代码转为 ES5。
            
    - **运行时机：** 在打包文件之前（预处理）。
        
- **Plugin (插件)：**
    
    - **作用：** “全能工具箱”。扩展 Webpack 的功能，覆盖整个构建周期。
        
    - **功能：** 执行更广泛的任务，如打包优化、资源管理、注入环境变量等。
        
    - **例子：**
        
        - `HtmlWebpackPlugin`：自动生成 HTML 文件并注入打包后的 JS。
            
        - `CleanWebpackPlugin`：打包前清空 dist 目录。
            
        - `MiniCssExtractPlugin`：将 CSS 提取为独立文件。
            
    - **运行时机：** 贯穿整个 Webpack 构建生命周期 (Lifecycle)。

### 19.Options API (Vue 2) vs Composition API (Vue 3)

| **特性**   | **Options API (Vue 2)**                                                    | **Composition API (Vue 3)**                                   |
| -------- | -------------------------------------------------------------------------- | ------------------------------------------------------------- |
| **代码组织** | **基于选项 (Option-based)**。代码按性质拆分：数据放 `data`，方法放 `methods`，计算属性放 `computed`。 | **基于逻辑 (Logic-based)**。代码按功能/业务逻辑拆分。同一个功能的变量、方法、生命周期可以写在一起。   |
| **逻辑复用** | 主要依靠 **Mixin**。缺点是命名容易冲突、数据来源不清晰（不知道某个变量是从哪个 Mixin 混入的）。                   | 主要依靠 **Composables (组合式函数)**。就像普通的 JS 函数一样引入，来源清晰，无命名冲突，极其灵活。 |
| **类型支持** | 对 TypeScript 支持较差，类型推断困难。                                                  | 对 **TypeScript** 支持极好，大部分情况能自动推断类型。                           |
| **上下文**  | 严重依赖 `this` 指向。                                                            | 在 `setup()` 中没有 `this`，变量和方法直接定义直接使用，减少了 `this` 指向造成的困扰。      |
| **打包体积** | 即使没用到的选项（如 watch），打包时也难剔除 (Tree-shaking 困难)。                               | 按需引入 (import)，未使用的功能容易被 Tree-shaking 掉，体积更小。                  |

### 20.Vue 3 生命周期钩子的变化

Vue 3 的生命周期主要有两个大的变化：

1. **销毁阶段的命名改变了**（为了与挂载 `mount` 对应，语义更准确）。
    
2. **引入了 `setup` 阶段**，并为 Composition API 提供了对应的 `onXXX` 函数。
    

#### 详细映射表

|**Vue 2 Options API**|**Vue 3 Composition API (在 setup 中使用)**|**说明**|
|---|---|---|
|`beforeCreate`|**不需要**|`setup()` 本身就在组件创建之前执行，所以直接在 `setup` 里写代码即可。|
|`created`|**不需要**|同上。`setup()` 取代了这两个钩子。|
|`beforeMount`|`onBeforeMount`|挂载前。|
|`mounted`|`onMounted`|**挂载完成 (最常用)**。DOM 已生成。|
|`beforeUpdate`|`onBeforeUpdate`|数据变了，视图还没更新。|
|`updated`|`onUpdated`|视图更新完成。|
|`beforeDestroy`|**`onBeforeUnmount`**|**(名称变化)** 卸载前。|
|`destroyed`|**`onUnmounted`**|**(名称变化)** 卸载完成。|
|`errorCaptured`|`onErrorCaptured`|捕获子组件错误。|
|-|`onRenderTracked`|**(新增)** 调试用，检查依赖收集。|
|-|`onRenderTriggered`|**(新增)** 调试用，检查触发更新。|

**关键总结 (面试话术)：**

1. **`setup` 取代了创建阶段**：在 Vue 3 的 Composition API 中，我们不再使用 `beforeCreate` 和 `created`，直接把逻辑写在 `setup` 函数体里就行。
    
2. **销毁变为卸载**：Vue 2 的 `Destroy` 变成了 Vue 3 的 `Unmount`，语义更加规范（对应 React 的 unmount）。
    
3. **函数式调用**：所有的生命周期钩子都需要从 `vue` 中 `import` 引入，然后传入回调函数来使用（例如 `onMounted(() => { ... })`）。

### 1. 对 Vue 的 MVVM 有什么理解？

这是考察你对框架宏观设计的理解。

- **回答核心：**
    
    - **M (Model)：** 数据层（比如 Vue 中的 `data`），负责业务数据。
        
    - **V (View)：** 视图层（DOM），负责页面展示。
        
    - **VM (ViewModel)：** 视图模型层（Vue 实例）。它是连接 View 和 Model 的桥梁。
        
- **关键点：**
    
    - MVVM 实现了 **视图** 和 **模型** 的**解耦**。
        
    - 开发者只需要关注数据（Model）的变化，ViewModel 会自动通过**数据绑定**将数据的变化更新到视图上；同时通过**DOM 事件监听**把视图的操作同步回数据。
        
    - **核心优势：** 减少了大量的 DOM 操作，提高了开发效率。
        

### 2. 对 Vue 的数据双向绑定怎么理解？

- **回答核心：**
    
    - **语法糖：** 双向绑定主要体现在 `v-model`指令上，它本质上是 `value` 属性绑定 + `input` 事件监听的语法糖。
        
    - **原理：**
        
        - **数据 -> 视图：** 依靠响应式系统（Vue 2 的 `Object.defineProperty` 或 Vue 3 的 `Proxy`）。
            
        - **视图 -> 数据：** 依靠原生的 DOM 事件（如 `input`、`change`）监听用户输入，然后更新数据。
            

### 3. JS 的事件循环 (Event Loop) 机制说一下

这是 JavaScript 最难也是最重要的机制之一，面试必问。建议配合简单的流程图记忆。

- **回答步骤：**
    
    1. **单线程：** JS 是单线程的，同一时间只能做一件事。
        
    2. **执行栈 (Stack)：** 同步代码直接在执行栈中执行。
        
    3. **任务队列 (Queue)：** 异步任务会被挂起，完成后放入队列。队列分为 **宏任务 (Macro-task)** 和 **微任务 (Micro-task)**。
        
    4. **循环过程：**
        
        - 先执行完所有的**同步代码**。
            
        - 然后清空当前的 **微任务队列**（如 `Promise.then`, `process.nextTick`, Vue 的 `nextTick`）。
            
        - 最后从 **宏任务队列**（如 `setTimeout`, `setInterval`, I/O）中取出一个执行。
            
        - 重复以上步骤。
            
- **一句话总结：** “同步 > 微任务 > 宏任务”。
    

### 4. H5 那边的节流 (Throttle) 和防抖 (Debounce)

这也是手写代码的高频题，一定要分清楚概念。

- **防抖 (Debounce)：**
    
    - **概念：** 也就是“回城被打断”。触发事件后，等待 N 秒再执行；如果在 N 秒内又触发了，则**重新计时**。
        
    - **场景：** 搜索框输入（用户输完字才发请求）、窗口大小调整（resize）。
        
- **节流 (Throttle)：**
    
    - **概念：** 也就是“技能冷却”。规定在单位时间内，只能触发一次函数。无论你点多快，它都是**按固定频率执行**。
        
    - **场景：** 滚动加载（scroll）、防止按钮多次重复点击。
        

### 5. ES7 里面 async/await 有使用过吗？

- **回答：**
    
    - **用过：** 它是目前处理异步操作最优雅的方案。
        
    - **本质：** 它是 Generator 函数 + Promise 的语法糖。
        
    - **优点：** 它可以让异步代码看起来像同步代码一样，从上往下执行，避免了 `.then` 链式调用的嵌套，代码可读性更强。
        
    - **错误处理：** 结合 `try...catch` 语句来捕获异步操作中的错误，非常方便。
        

### 6. 你大概说一下 Vue 的生命周期

### 1. var, let, const 的具体区别 (JS 基础)

虽然之前提过它是 ES6 特性，但面试官通常会问得很细。

- **作用域 (Scope)：**
    
    - `var`: **函数作用域**。在函数外部定义的 `var` 变量是全局的（挂载在 window 上）。
        
    - `let` / `const`: **块级作用域** (Block Scope)。只在 `{}` 大括号内部有效。
        
- **变量提升 (Hoisting)：**
    
    - `var`: 存在变量提升。可以在声明之前使用（值为 `undefined`）。
        
    - `let` / `const`: 不存在提升。在声明前使用会报错（ReferenceError），这被称为**暂时性死区 (TDZ)**。
        
- **重复声明与修改：**
    
    - `var`: 允许重复声明。
        
    - `let`: 不允许在同一作用域重复声明。
        
    - `const`: 声明时必须赋值，且**引用地址不可修改**（但如果 const 指向一个对象，对象的属性是可以改的）。
        

### 2. call, apply, bind 的区别 (this 指向)

这三个都是用来改变函数内部 `this` 指向的。

- **共同点：** 第一个参数都是 `this` 要指向的对象。
    
- **区别 (口诀记忆)：**
    
    - **执行时机：** `call` 和 `apply` 会**立即执行**函数；`bind` 不会立即执行，而是**返回一个新的函数**。
        
    - **传参方式：**
        
        - `call` (Comma): 参数是一个个传的 `fn.call(obj, arg1, arg2)`。
            
        - `apply` (Array): 参数是放在数组里的 `fn.apply(obj, [arg1, arg2])`。
            
- **使用场景：**
    
    - `apply`: 经常用于数组操作，比如求数组最大值 `Math.max.apply(null, arr)`。
        
    - `bind`: 经常用于 React/Vue 的事件回调中，或者保存 `this` 上下文。


### 4. 网络协议相关 (HTTP/HTTPS, TCP/UDP)

面试通常问得很基础，重点掌握以下两点：

- **HTTP vs HTTPS:**
    
    - **HTTP:** 明文传输，不安全，端口 80。
        
    - **HTTPS:** HTTP + **SSL/TLS** 协议。数据是加密的，更安全，端口 443。需要申请证书。
        
- **TCP vs UDP (传输层协议):**
    
    - **TCP (可靠)：** 面向连接，“三次握手”建立连接。保证数据不丢失、不乱序。**场景：** 网页浏览、文件下载、邮件。
        
    - **UDP (快)：** 无连接，发出去就不管了，可能会丢包。**场景：** 视频直播、在线游戏（对实时性要求高，允许少量丢包）。

### 第一部分：JavaScript 核心原理 (重中之重)

**1. JS 类型判断有哪些方式？**

- **`typeof`**: 适合判断基本类型（string, number, boolean, undefined）。
    
    - _缺陷_：`typeof null === 'object'`；无法区分数组和对象（都返回 'object'）。
        
- **`instanceof`**: 判断对象的原型链中是否包含某个构造函数的 `prototype`。
    
    - _场景_：`arr instanceof Array`。
        
- **`Object.prototype.toString.call(val)` (万能公式)**:
    
    - 最准确，返回 `[object String]`, `[object Array]` 等。
        

**2. 原型链 (Prototype Chain) 是什么？**

- **核心概念：** 每个对象都有一个 `__proto__` 属性指向它的原型对象；原型对象也有自己的 `__proto__`，一层层向上找，直到 `null`。
    
- **作用：** 实现继承。当访问对象的属性时，如果自己没有，就去原型链上找。
    

**3. `new` 关键字发生了什么？ (手写 new 的步骤)**

1. 创建一个空对象 `{}`。
    
2. 将这个空对象的 `__proto__` 指向构造函数的 `prototype`。
    
3. 执行构造函数，将 `this` 绑定到这个新对象上。
    
4. 如果构造函数返回了一个对象，就返回该对象；否则返回新创建的对象。
    

**4. 0.1 + 0.2 为什么不等于 0.3？怎么解决？**

- **原因：** JS 使用 IEEE 754 双精度浮点数存储，二进制转换时会产生无限循环小数，导致精度丢失。
    
- **解决：**
    
    - **乘除法：** 先变成整数计算 `(0.1 * 10 + 0.2 * 10) / 10`。
        
    - **`toFixed(2)`：** 保留两位小数（注意返回的是字符串）。
        
    - **第三方库：** `decimal.js` 或 `bignumber.js`。
        

**5. `map` 和 普通对象 (`Object`) 的区别？**

- **键 (Key) 的类型：** Object 的键只能是字符串或 Symbol；Map 的键可以是**任意类型**（包括对象、函数）。
    
- **顺序：** Map 按照插入顺序遍历；Object 的遍历顺序在不同浏览器下可能不一致。
    
- **性能：** 频繁增删键值对时，Map 性能通常更好。

### 第四部分：工程化与 Promise 补充

**11. `Promise.all` 其中一个挂了怎么办？**

- **打包体积优化：**

**1. 闭包 (Closure) —— _必考_**

- **概念：** 简单说就是 **“函数嵌套函数”**。内部函数可以访问外部函数的变量，即使外部函数已经执行完毕，这些变量依然被保存在内存中，不会被垃圾回收。
    
- **用途：**
    
    - **数据私有化：** 防止全局变量污染（比如计数器）。
        
    - **防抖节流：** 利用闭包保存定时器 `timer`。
        
- **缺点：** 滥用会导致内存泄漏（变量一直不释放）。
    

**2. 事件委托 (Event Delegation) —— _DOM 操作必考_**

- **原理：** 利用 **事件冒泡** 机制。
    
- **做法：** 不在每个子元素（如 `<li>`）上绑定事件，而是把事件绑定在 **父元素**（如 `<ul>`）上。
    
- **好处：**
    
    1. **性能更好：** 减少了内存中事件监听器的数量。
        
    2. **动态元素有效：** 后续新增的 `<li>` 也能自动响应点击，不需要重新绑定。
        

**3. JS 实现继承的方式**

- **实习生回答重点：**
    
    - **ES6 `class` 继承 (推荐)：** 使用 `extends` 关键字，超级简单，语法像 Java/C++。
        
        JavaScript
        
        ```
        class Dog extends Animal { ... }
        ```
        
    - **ES5 组合继承 (了解即可)：** 结合了原型链继承和构造函数继承。
        
- **注意：** 如果面试官让你手写 ES5 继承，对于实习生来说有点偏难，如果写不出来，重点说清楚 ES6 的 `class` 即可。
    

**4. `v-show` 和 `v-if` 的区别 —— _Vue 基础必考_**

- **手段不同：**
    
    - `v-if`：**真正的条件渲染**。如果不满足条件，DOM 元素压根**不会被渲染**（在 DOM 树里找不到）。
        
    - `v-show`：**CSS 切换**。元素一直都在 DOM 里，只是通过 `display: none` 来控制显示隐藏。
        
- **场景：**
    
    - 频繁切换显示状态用 `v-show` (性能好)。
        
    - 条件很少改变，或者一开始可能就不显示，用 `v-if`。
        

**5. 这里的 `parseInt()` 和 `Number()` 有什么区别？**

- **`parseInt(string)`：** 它是**解析**。它会尝试把字符串开头是数字的部分读出来，遇到非数字就停止。
    
    - `parseInt('12px')` -> `12`
        
- **`Number(value)`：** 它是**转换**。只要字符串里混入了非数字字符，它就直接放弃，返回 `NaN`。
    
    - `Number('12px')` -> `NaN`

### 第三部分：算法与数据结构 (基础)

**8. 冒泡排序 (Bubble Sort) —— _最基础的排序_**

- **原理：** 两两比较，如果前一个比后一个大，就**交换位置**。每一轮比较下来，最大的数就像“泡泡”一样浮到了最后面。
    
- **口述思路：** “用双层循环，外层控制轮数，内层两两比较并交换。”
    

**9. Set 去重的原理是什么？**

- **用法：** `[...new Set(array)]` 是最常用的数组去重方法。
    
- **原理：** `Set` 数据结构内部判断两个值是否不同，类似于 `===` (全等)，但有一点不同：在 Set 看来，`NaN` 和 `NaN` 是相等的（虽然 JS 里 `NaN !== NaN`），所以它能去重 `NaN`。
    

**10. 递归的特点**

- **定义：** 函数自己调用自己。
    
- **关键点 (必须说)：** 必须有一个 **“出口” (终止条件)**，否则会死循环导致栈溢出 (Stack Overflow)。
    
- **场景：** 深拷贝、渲染树形菜单（Tree组件）。

### 第一部分：HTML/CSS 基础细节 (考察细心程度)

**1. `src` 和 `href` 的区别**

- **`src` (Source)：** 指向**外部资源**的位置（如 JS 脚本、图片）。浏览器解析到 `src` 会**暂停**页面渲染去下载并执行它（所以 JS 一般放底部）。
    
- **`href` (Hypertext Reference)：** 指向**网络资源**的位置（如 CSS）。浏览器识别到它会**并行下载**，不会阻塞页面渲染。
    

**2. `alt` 和 `title` 的区别**

- **`alt`：** 图片**加载失败**时显示的文字（为了可访问性）。
    
- **`title`：** 鼠标**悬停**在元素上时显示的提示文字。
    

**3. CSS 单位：`em`, `rem`, `vw`, `vh` 的区别**

- **`em`：** 相对于**父元素**的字体大小。
    
- **`rem` (root em)：** 相对于**根元素 (`html`)** 的字体大小（移动端适配常用）。
    
- **`vw` / `vh`：** 相对于**视口 (Viewport)** 的宽/高。`1vw` = 视口宽度的 1%。
    

**4. 什么是盒模型 (Box Model)？**

- **组成：** Content（内容） + Padding（内边距） + Border（边框） + Margin（外边距）。
    
- **两种标准 (面试坑点)：**
    
    - **标准盒模型 (`box-sizing: content-box`)：** 设置的 `width` 只是内容的宽度。总宽度 = width + padding + border。
        
    - **IE/怪异盒模型 (`box-sizing: border-box`)：** 设置的 `width` 包含了 content + padding + border。**（推荐开发中使用这个，布局更方便）**。
        

**5. 什么是回流 (Reflow) 和重绘 (Repaint)？**

- **回流 (Reflow)：** 布局变了（比如改变宽高、窗口大小调整、增删 DOM）。浏览器需要重新计算元素位置。**消耗极大**。
    
- **重绘 (Repaint)：** 样式变了但没影响布局（比如改变颜色 `color`、`background`）。**消耗较小**。
    
- **结论：** **回流一定会触发重绘，但重绘不一定触发回流。**

### 第三部分：Vue 框架核心 (避坑指南)

**10. 为什么 Vue 组件里的 `data` 必须是一个函数？**

- **核心原因：** 为了**数据独立性**。
    
- **解释：** 组件是可以复用的。如果 `data` 是一个对象，那所有复用的组件都会**共享**同一个内存地址的数据，改一个全乱了。写成函数，每次复用都会返回一个新的对象副本。
    

**11. `computed` (计算属性) 和 `watch` (侦听器) 的区别 —— _必考_**

- **`computed`：**
    
    - 有**缓存**（依赖的数据没变，就不会重新计算）。
        
    - 适合**多个数据影响一个数据**（如：购物车总价 = 单价 * 数量）。
        
    - 不支持异步。
        
- **`watch`：**
    
    - 无缓存。
        
    - 适合**一个数据影响多个操作**，或者执行**异步操作**（如：搜索框输入变化后发请求）。
        

**12. `$route` 和 `$router` 的区别**

- **`$route` (当前路由信息对象)：** 获取当前页面的**数据**（如 `params`, `query` 参数, `path`）。
    
- **`$router` (全局路由实例)：** 执行**操作**（如 `push`, `replace`, `go` 跳转）。
    

**13. Vuex / Pinia 是做什么的？ (Vue 全家桶)**

- **作用：** **全局状态管理**。解决多层级组件、兄弟组件之间复杂的数据通信问题。
    
- **Vuex 核心概念 (实习生记住这3个就行)：**
    
    - **State：** 存数据。
        
    - **Mutations：** 修改数据的唯一方式（必须是**同步**）。
        
    - **Actions：** 处理**异步**操作（如发请求），然后提交 Mutation。
        

**14. 什么是虚拟 DOM (Virtual DOM)？**

- **定义：** 用 JS 对象来模拟真实的 DOM 结构。
    
- **优点：**
    
    - **性能优化：** 通过 Diff 算法比较新旧差异，只更新变化的 DOM，避免暴力重绘。
        
    - **跨平台：** 虚拟 DOM 可以渲染到浏览器，也可以渲染到安卓/iOS (React Native / Weex)。
        

**15. 路由守卫 (Navigation Guards) 是什么？**

- **作用：** 在路由跳转前进行拦截。
    
- **场景：** **判断用户是否登录**。
    
- **代码演示：** `router.beforeEach((to, from, next) => { ... })`。
