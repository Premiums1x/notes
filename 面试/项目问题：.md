面试问题：（核心考点：复杂的交互逻辑、音频处理、正则表达式）
1.“你提到的‘歌词实时滚动’具体是怎么实现的？”
简历原话：“利用正则算法解析 LRC 文件，实现了歌词实时滚动功能。”

标准答案：
- **解析原理：** “后端返回的歌词是一长串字符串，每一行都有时间戳，比如 `[00:12.34]歌词内容`。我写了一个函数，用**正则表达式**去匹配每一行，提取出‘时间’和‘内容’，转换成一个数组对象 `{ time: 12.34, text: '歌词内容' }`。”
    
- **滚动原理：** “我监听了 `<audio>` 元素的 **`timeupdate` 事件**（划重点！）。每当歌曲播放进度更新，我就拿当前的 `currentTime` 去遍历歌词数组，找到**当前时间对应的那一行歌词的索引**（Index），然后通过 CSS 的 `transform: translateY` 向上移动整个歌词列表。”

- **难点（假如问遇到什么坑）：** “高亮歌词不仅要根据时间，还要考虑用户手动拖动进度条的情况，有时候需要做防抖处理，不然滚动会很跳跃。”

2.“你的 Axios 封装里，为什么要‘添加时间戳防止接口缓存’？”
原话：“配置请求拦截器添加时间戳防止接口缓存。”

标准答案：

- **原因：** “因为我用的是网易云的开源接口，GET 请求有时候会被浏览器或者代理服务器缓存。如果用户刚把一首歌加到‘喜欢’列表，刷新页面却没更新，这就是缓存导致的。”
    
- **实现：** “我在 Axios 的 **Request Interceptor（请求拦截器）** 里，给每个 `config.params` 自动加上了一个 `_t: Date.now()` 参数。这样每次请求的 URL 都不一样，强制浏览器去拉取最新的数据。”

3.播放器状态如何管理：
原话：“结合 Pinia 管理全局播放状态。”
标准答案：
- “因为播放器组件是全局的（通常在页面底部），但‘播放/暂停’按钮可能在歌单详情页，也可能在首页。组件层级很深，用 Props 传值太乱了。”
    
- “所以我建立了一个 `usePlayerStore`。里面存放 `isPlaying`（是否播放）、`currentSong`（当前歌曲信息）、`playList`（播放列表）。这样任何组件想要切换歌曲，只需要调用 Store 里的 action，比如 `playSong(id)`，不用关心具体的组件通信。”

在其中怎么用pinia的？
：“因为播放器是全局的，不管用户跳到哪个页面，歌都不能停。 所以我建了一个 `usePlayerStore`，在 **State** 里存了 `currentSong`（当前歌曲）和 `isPlaying`（播放状态）。 当用户点击歌单里的歌曲时，我调用 **Action** 里的 `playSong(song)` 方法，直接修改 State。底部的播放条组件监听了这个 State，就自动开始播放了。”

项目二：仿知乎日报app
1.“你简历里写的‘Rem 移动端适配’具体是怎么配置的？”
原话：配置 postcss-pxtorem 与 amfe-flexible 实现 Rem 移动端适配。

标准答案：
- **原理：** “我采用了**Rem 方案**。`amfe-flexible` 这个库会根据当前设备的屏幕宽度，动态设置 `html` 根标签的 `font-size`。”
    
- **自动化：** “我在开发时直接写 `px` 单位（比如设计稿是 375px 或 750px），然后通过 **PostCSS** 的插件 `postcss-pxtorem`，在编译打包时自动把 `px` 转化成 `rem`。这样就不用我自己手动算了，保证在 iPhone 和安卓大屏上元素比例是一致的。”

2.“文章收藏的‘数据去重’你是怎么做的？”
答案：“收藏列表其实就是一个数组。当用户点击收藏时，我使用数组的 **`some()` 方法**或者 **`find()` 方法**，先判断一下当前文章的 ID 是否已经存在于这个数组里了。如果存在就提示‘已收藏’，不存在才 `push` 进去。防止出现两条一模一样的文章。”

3.- “你的登录功能和收藏功能怎么结合 Pinia 的？”
答：“登录成功后，后端会返回用户信息（比如头像、名字）。如果不存起来，换个页面就没了。 所以我把用户信息存到了 Pinia 的 **State** 里。这样，‘个人中心页’和‘评论区’都可以直接从 Store 里取用户的头像来展示，不需要到处传参。 对于‘收藏文章’，我也是在 Pinia 里维护了一个 `collectList` 数组，用户点击收藏，就通过 Action 把文章 push 进去。”

4.“你遇到了什么样式兼容性问题吗？”
答：“遇到过。比如 iOS 上的 **SafeArea（安全区域）** 问题，底部的导航栏在 iPhone X 以上机型会被小黑条遮挡。我使用了 Vant 提供的安全区适配方案，或者自己在 CSS 里写 `padding-bottom: constant(safe-area-inset-bottom);` 来解决。”
